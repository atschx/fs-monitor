# FSMonitor 使用指南

适用对象：已安装或已构建的 **macOS** FSMonitor **测试预发布**。本文只描述当前界面里真实存在的流程。

相关入口：

- 仓库说明：[README.md](../README.md)
- 介绍页：https://blog.atschx.me/fs-monitor/
- 当前预发布：[v0.1.1-beta.1](https://github.com/atschx/fs-monitor/releases/tag/v0.1.1-beta.1)（包内 0.1.1；早期 [v0.1.0-test](https://github.com/atschx/fs-monitor/releases/tag/v0.1.0-test) 仍保留）

## 1. 准备

- 系统目标：macOS 13+；当前公开测试包架构为 **仅 Apple Silicon（arm64）**
- 来源：优先 GitHub Release **v0.1.1-beta.1** 中的 `FSMonitor.app.zip`（核对该页 SHA-256）；或本机（arm64 Mac）`scripts/package-macos-app.sh`
- 测试包为 **ad-hoc 签名**，**未公证**；`spctl --assess` 为 rejected（预期）
- **同一包在真实 Mac 上的 GUI / 交互尚未验收**（负责人已跳过人工验证；不得视为通过）。请区分「CI/发布打包」与「实机验收」
- **Liquid Glass 未实现、未验证**；需求仍开放
- 首次打开说明不保证各系统/策略下表现一致：选中 App → 右键「打开」。不要关闭 Gatekeeper 或 SIP
- 图标：Nova 选定 D2。已知 16/32 眼神弱、大尺寸偏前；未 Dock 实测。设计稿不是运行截图
- 退出应用后不保留监控会话、证据或扫描结果
## 2. 基本流程

### 2.1 选择目录

1. 打开 FSMonitor
2. 点击「选择目录」
3. 在系统面板中选一个目录并确认

选择之前**不会**扫描。应用不上传路径，也不删除文件。

### 2.2 建立基线

1. 目录已选中后，点击「建立基线」（若已有基线则为「重新建立基线」）
2. 等待扫描结束。可随时「取消扫描」；取消后不会用半次扫描替换已有基线
3. 界面会显示基线逻辑大小、分配块（若可读）等

重新建立基线会清空当前操作证据；磁盘上的文件不会被删除。

### 2.3 开始 / 停止监控（可选）

1. 在已有基线后，点击「开始监控」
2. 应用开始接收所选目录下的 FSEvents
3. 点击「停止监控」结束接收。停止监控**不会**删除目录

开始监控后才会接收 FSEvents。

### 2.4 再次扫描（复扫）

1. 在监控期间或之后，点击「复扫查看变化」
2. 对照基线查看新增 / 删除 / 变大 / 变小 / 覆盖缺口，以及顶层子项汇总
3. 可用排序：增长降序、增长升序、当前大小、路径

### 2.5 阅读证据

- **操作证据**：来自 FSEvents。每条有时间、相对路径、标志；**没有 PID**。路径重叠 ≠ 因果
- **进程读写**：来自 `proc_pid_rusage` 的全进程计数差值。标签会写明那是全进程计数，不是此目录的 I/O。不可获得的计数不会显示成 0
- 摘要中的「基线/当前」会标注各自的**扫描时刻**。若最近一次扫描失败或取消，界面会标明数字仍来自上一次成功采用的结果
- 开始/停止监控时若显示「采样中」，请等待结束，避免重复点击叠在旧进程差值上
- 「有 N 条路径无法读取」表示**扫描已完成但部分路径缺失**，与整次扫描失败（结果未采用）不同。旧/新一侧因权限、无法列出目录或未进入挂载点而未覆盖的路径，差异中记为**覆盖缺口**，不作确定删除或新增；双方都覆盖到且确实消失的路径仍记为删除
- 界面固定提示：时间相近不是因果；不能做 100% 物理 IO 归因

证据条数有界面保留上限；更早的可能被丢弃，界面会提示丢弃数量。

## 3. 权限与边界

- 默认以当前用户运行，不需要 root，也不使用 Endpoint Security
- 访问桌面、文稿、下载等目录时，系统可能弹出隐私提示；那是 macOS 授权
- 被拒绝的路径会出现在「限制与错误」；合计不包含这些路径
- 可选：在「系统设置」中授予完全磁盘访问，以提高读取成功率。应用不会假装已经拥有它
- 符号链接不会跟到所选目录之外；其他挂载点不会进入
- 应用不会删除文件、结束进程、关闭 SIP，也不会上传扫描内容

## 4. 用隔离临时目录练习（可选）

仓库脚本只操作带标记的临时目录，避免误扫用户目录：

```bash
DIR=$(scripts/isolated-demo.sh prepare)
# 在应用中选择 $DIR，建立基线 → 开始监控
scripts/isolated-demo.sh grow "$DIR"
# 再次扫描，观察 data/cache.bin、logs/new.log 等
scripts/isolated-demo.sh cleanup "$DIR"
```

`cleanup` 要求目录内存在 `.fs-monitor-demo-marker` 且路径包含 `fs-monitor-demo`。

## 5. 未知项与已知缺口（不是功能）

以下**不是**当前版本能力，界面也不会伪装成已实现：

- 跨会话把历史扫描结果持久化后再回溯对比
- 整块磁盘 / 系统级 IO 仪表盘
- 「复制暂停」类归因或完整读写覆盖因果链
- 指向具体写入进程的确定性结论（FSEvents 无 PID）
- 正式 Developer ID 签名与 Apple 公证发行

## 6. 卸载

没有独立安装器时：

1. 退出 FSMonitor
2. 将 `FSMonitor.app` 移到废纸篓并清空（或删除你放置它的目录）
3. 本应用不会在未选择目录时扫描；若你曾授予「完全磁盘访问」，可在系统设置中自行撤销

## 7. 常见问题

**打不开 / 提示无法验证开发者？**  
测试包多为 ad-hoc 签名。使用「右键 → 打开」。不要关闭 Gatekeeper。

**为什么看不到是谁写入的？**  
FSEvents 不带 PID。进程表只是全进程旁证。

**数字对不上磁盘工具？**  
逻辑大小、分配块、压缩、稀疏、缓存、读不到的路径都会造成差异。不能 100% 物理 IO 归因。

**Linux 能跑吗？**  
不能启动界面。本项目只支持 macOS；CI 已不再跑 Linux 测试。

**没有下载按钮？**  
以 [Releases](https://github.com/atschx/fs-monitor/releases) 实际页面为准。若为空，请用源码构建或 CI 工件，不要假设存在未发布的安装包。
