fs-monitor

把目录变大这件事说清楚，而不是假装找到了凶手。

macOS 早期 demo：对选定目录建立空间基线，可选监控 FSEvents，再次扫描后对照差异。 进程读写只在系统真实返回时展示，用作旁证，不是目录级归因，也不能做 100% 物理 IO 归因。

当前能做什么

与仓库 README 一致，只写已经实现的能力。细节见使用指南。

  • 扫描所选目录的逻辑大小与（可读时的）分配块，建立基线后再扫描做差分。
  • 监控窗口记录 FSEvents 路径、标志与时间；事件没有 PID。
  • 若 proc_pid_rusage 成功，显示全进程磁盘计数差值；失败则「不可获得」。
  • 可取消扫描；不会用半次结果替换基线。默认不需要 root。

做不到什么

这些限制写在应用界面里，本页也不淡化。

  • 不能指出是哪个进程写入了该目录；全进程计数不是目标目录 I/O。
  • 时间接近不是因果；不能做 100% 物理 IO 归因。
  • 不是现状：持久化回溯、整盘 IO 仪表盘、复制/暂停归因、正式公证签名版。

如何获取

优先下载可双击的 FSMonitor.app；没有安装包时再源码构建。

  • GitHub Releases：以实际页面为准；列表为空表示尚无可下载发行物。
  • CI 工件：macOS 工作流上传的 FSMonitor-macos-app（需登录）。
  • 目标：macOS 13+，仅 arm64。CI 在 macos-15 arm64 打包通过 ≠ 同包已在真实 Mac 13 上完成交互验收。
  • 签名：ad-hoc；Gatekeeper/spctl 评估拒绝（预期）。首次打开说明不保证各系统通用；不要关闭系统保护。
  • 图标为本轮 Nova 选定的 D2；未使用 A/B/C 或含棋盘格参考底图。16/32 细节弱与大尺寸偏前为已知不足，非 Dock 实测通过。

更多步骤见 使用指南。
