fs-monitor

把目录变大这件事说清楚，而不是假装找到了凶手。

macOS 上的早期 demo：先对选定目录建立空间基线，监控窗口内记录文件系统事件，再次扫描后对照差异。 进程读写只在系统真实返回时展示，用作旁证，不是目录级归因。

它能说明什么

对照基线与再次扫描，给出可核验的空间变化与操作证据。

  • 常规文件逻辑大小（stat 的 st_size）在两次扫描之间的变化。
  • 能读到分配块时，同时给出 st_blocks × 512 的差值；这是已分配块，不是独占物理空间。
  • 硬链接按 inode 只计入合计一次；同一 inode 仍可能出现在多条路径上。
  • 监控期间，FSEvents 提供路径、事件标志与时间，作为操作证据。
  • 若 proc_pid_rusage 成功，界面显示全进程磁盘计数在两次采样之间的差值。

它不能说明什么

边界写在界面上，也不会在本页被淡化。

  • FSEvents 没有 PID，不能指出是哪个进程写入，也没有读取覆盖意义上的完整因果链。
  • 全进程计数不是目标目录的 I/O，也不能按路径拆开。
  • 采样时间、扫描时间与事件时间接近，只说明时间相关，不是因果关系。
  • 不能做 100% 物理 IO 归因。压缩、写时复制、稀疏文件、缓存、其他目录上的读写，以及读不到的路径，都会让数字对不上。
  • 调用失败时显示「不可获得」；应用不会把缺失值填成 0，也不会猜测。

实际技术边界

以下描述来自当前公开源码与仓库说明，不是路线图。

平台
Swift / SwiftUI，最低 macOS 13；Swift Package，无需单独 Xcode 工程文件。
空间差分
目录扫描建立基线，再次扫描后做路径级差分与子树汇总。
事件来源
FSEvents 文件事件流；默认不需要 root，也不使用 Endpoint Security。
进程旁证
macOS 上通过 proc_pid_rusage 等接口采样全进程磁盘计数；失败则不展示数值。
权限
默认以当前用户运行。访问受保护目录时可能触发系统隐私提示；完全磁盘访问需用户在系统设置中自行授予。
不做的事
不删除文件、不结束进程、不关闭 SIP、不上传扫描路径或目录内容；选择目录前不扫描。

在 Mac 上构建

需要 macOS 13+ 与 Xcode 15+（Swift 5.9）。仓库目前没有 GitHub Releases 安装包。

swift test
swift build -c release --product FSMonitor
.build/release/FSMonitor

也可用隔离脚本 scripts/isolated-demo.sh 在带标记的临时目录里演示增长，避免误扫用户目录。
