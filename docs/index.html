fs-monitor

把目录变大这件事说清楚，而不是假装找到了凶手。

macOS 测试预发布 v0.1.1-beta.1（包内 0.1.1）：对选定目录建立空间基线，可选监控 FSEvents，再次扫描后对照差异。 进程读写只在系统真实返回时展示，用作旁证，不是目录级归因，也不能做程序—文件精确归因或 100% 物理 IO 归因。 退出后不保留会话。

当前能做什么

与仓库 README 一致，只写已经实现的能力。细节见使用指南。

  • 扫描所选目录的逻辑大小与（可读时的）分配块，建立基线后再扫描做差分；一侧未覆盖的路径记为覆盖缺口，不作确定删除/新增。
  • 监控窗口记录 FSEvents 路径、标志与时间；事件没有 PID。
  • 若进程采样成功，显示全进程磁盘计数差值；失败则说明未取得数据，不以 0 充数。
  • 可取消扫描；失败/取消不会用半次结果替换已有基线。停止监控与取消扫描相互独立。默认不需要 root。

做不到什么

这些限制写在应用界面里，本页也不淡化。

  • 不能指出是哪个进程写入了该目录；全进程计数不是目标目录 I/O。
  • 时间接近不是因果；不能做 100% 物理 IO 归因。
  • 不能还原监控开始前的历史；退出后不保存会话、证据或扫描结果。
  • 不是现状：持久化回溯、整盘 IO 仪表盘、正式公证签名版、已验收的 Liquid Glass 外观。

如何获取

下载可双击的 FSMonitor.app；以本预发布 Release 为准，不要用设计图或 PR Actions 预览包冒充。

  • GitHub Release v0.1.1-beta.1：下载 FSMonitor.app.zip，并核对该页公布的 SHA-256 / BUILD_INFO.txt。
  • 绑定提交（最终 main）：7c35ba19e18b5ba3fbc9978e402b9e15114f653a（合并 PR #4）。早期 v0.1.0-test 仍保留。
  • 目标：macOS 13+，仅 arm64。最低系统目标 ≠ 已在 macOS 13 完成交互验收。
  • 签名：ad-hoc；未公证；Gatekeeper/spctl 评估拒绝（预期）。首次打开不要关闭系统保护。
  • GUI / 同包实机交互未验收（负责人已跳过人工验证；不得写成通过）。Liquid Glass 未实现、未验证，需求仍开放。
  • 图标为 D2 主题接入；设计稿不是本包运行截图。
